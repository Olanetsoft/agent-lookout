These notes record what Agent Lookout reads from Oh My Pi, where each value comes from, and what breaks when Oh My Pi changes. When the adapter stops working, start here.

## How it reads Oh My Pi, and why

Oh My Pi is a fork of Pi, and keeps Pi's header, entry types and folder variables. Its files differ from Pi's in five ways that Pi's reader cannot take: a title slot on line 1 with the header on line 2, no `session_info` line, a slot rewritten in place, project folders whose names begin with `-`, and the `session_exit` and `tool_execution_start` lines. So it is an adapter of its own, as Droid's is, and shares the pieces of Pi's that fit.

Nothing on disk says whether a session's process runs: the lease holds no pid and cannot be checked without taking or trying it, which Agent Lookout never does. So a session's status comes from three things: the exit line, `ps`, and when the computer started. No Oh My Pi program is run. Oh My Pi documents `omp session lease --json` and RPC `get_session_lease` for other programs (`DOC:628`; `CA/commands/session.ts:9-10`), but Agent Lookout's adapters run no program of an agent's, only `ps`, and running `omp` would load its `.env` files (`CA/cli.ts:121-125`) and create and prune `logs/` (`UT/logger.ts:193-270`, `:432-435`). It reads the files alone, as [Adding an adapter](../../CONTRIBUTING.md#adding-an-adapter) asks of a tool whose state can be read so.

## Where it looks

The first rule that applies gives the sessions folder (`folders.ts`):

1. `AGENT_LOOKOUT_OMP_HOME`, Agent Lookout's own setting, names the agent folder, and `sessions` in it is read. A named folder with no sessions is an answer, not a missing Oh My Pi.
2. `PI_CODING_AGENT_SESSION_DIR`, when it is a whole path, holds the session files themselves, with no project folders, for every profile (`CA/cli/args.ts:263`). One that is not a whole path, `~/...` among them, is passed over, as Oh My Pi resolves it from the folder it was started in (`CA/session/session-manager.ts:1081-1083`), and the card says so.
3. A named profile: `OMP_PROFILE` when it is set, even to nothing, else `PI_PROFILE`, trimmed (`UT/dirs.ts:64-92`). A blank one or `default` is the default profile, and so is a name Oh My Pi refuses, as it then does not start (`UT/dirs.ts:43`, `:54-83`). For a named profile `PI_CODING_AGENT_DIR` is not read, and the folder is `~/.omp/profiles/<name>/agent/sessions` (`UT/dirs.ts:116-123`, `:361-367`).
4. `PI_CODING_AGENT_DIR`, for the default profile, when it is a whole path: `sessions` in it. One equal to `~/.omp/profiles/<PI_PROFILE>/agent` was set by a parent's profile, and is not followed (`UT/dirs.ts:470-486`). One that is `~/.omp/agent` counts as the default (`UT/dirs.ts:368`). One that is not a whole path is passed over, and the card says so.
5. Otherwise `~/.omp/agent/sessions`.

`PI_CONFIG_DIR` renames `.omp`, always under the home folder (`UT/dirs.ts:332-334`). On macOS and Linux, with `XDG_DATA_HOME` a whole path and no other agent folder named, the default folder is `$XDG_DATA_HOME/omp/sessions` once `$XDG_DATA_HOME/omp` is there, and a named profile's is `$XDG_DATA_HOME/omp/profiles/<name>/sessions` once that profile's folder is (`UT/dirs.ts:368-404`). Whether it is there is one `stat`, as Oh My Pi's own look is, made on the first poll and once a minute after. When the answer moves, the finder and the reader start afresh, and the Sources card names the new folder. A relative `XDG_DATA_HOME` is not followed. On Windows the folder is `%USERPROFILE%\.omp\agent\sessions`.

These are not followed: `--session-dir`, `--profile` and `--session`, the `.env` files Oh My Pi loads, `~/.env`, `~/.omp/.env`, `~/.omp/agent/.env` and a project's `./.env` (`UT/env.ts:290-293`, `:383-399`), session stores an SDK program can name, in Redis or SQL (`CA/session/redis-session-storage.ts:102-121`), and the `custom-session-files` list.

## Finding the files

Pi's finder lists the sessions folder every 2 seconds, looks up each folder in it whose name begins with `-` with one `lstat`, and lists one again only when its modified time moves, and every folder once a minute. Oh My Pi names a project's folder `-` and its path under the home folder, `-tmp-` and its path under the temporary folder, or `--<path>--` (`CA/session/session-paths.ts:47-55`, `:79-124`), so all three begin with `-`. A folder of `omp gc --compress`'s, `.omp-gc-compress-*`, and the older hashed folders `home-*`, `tmp-*` and `abs-*`, which Oh My Pi moves on its next look (`DOC:47`), are not listed. It looks up each `.jsonl` file, as Oh My Pi's own list takes any (`CA/session/session-listing.ts:657`, `:707`), at most the 200 written last in the last day, and passes over a link, anything that is not an ordinary file, and the folder of each session's own files beside it, `<time>_<id>/`, which holds subagents' transcripts (`CA/session/session-storage.ts:1416-1417`). Lock files `.<name>.jsonl.lock` and `.lock.os`, temporary `.tmp` files and `.bak` copies do not end in `.jsonl`. Of two files that hold one ID, the newer is shown.

## The session file

A file is opened only when its size, modified time or identity changes, or while its title slot is not settled, read-only, without following a link at its name and, in a project folder, only when that folder is a real folder. Its last write is the open file's modified time when that is later than its `lstat`'s. Each open is short.

### The title slot

The first line is exactly 256 bytes with its line break: `{"type":"title","v":1,"title":"…","source":"auto"|"user","updatedAt":"…","pad":"…"}`, with no `source` while no title is set (`CA/session/session-title-slot.ts:21-59`, `:111-122`). Oh My Pi rewrites it in place, with a plain write and no lock, when the title changes (`CA/session/session-storage.ts:1054-1071`), so a read can catch half of each. So:

- The first 256 bytes are read on every change, and again on each poll until two reads in a row gave the same bytes, the later at least 2 seconds after the file's modified time, as a disk can keep a write's time rounded down. A rewrite of the same size within those 2 seconds is still read.
- A title is taken only from two reads in a row that agree. A slot not as Oh My Pi writes it keeps the title from before.
- The slot is compared as bytes. Its title, one JSON string, is turned into text only when the bytes after it are `,"source":"user"` or `,"source":"auto"`, and for `auto` only when the session is not one Oh My Pi made from a Codex session.
- A file whose first 256 bytes are not a slot, as an older Oh My Pi's or a Pi session's in a folder both use, is not shown, and nothing of it is turned into text.

### The header

The second line is the header, as Pi's, at version 3 (`CA/session/session-entries.ts:17`, `:57-85`; `CA/session/session-manager.ts:2091-2100`). The 64 KiB and 64 bytes after the slot, or as many as the file holds, are read in one piece, when the file's identity changes and on each change until a header is found. The header, from byte 256 to its line break within the first 64 KiB of them, is parsed by Pi's `parseHeader`, given Oh My Pi's newest version. Only `id`, `timestamp`, `cwd` and `version` are kept. The header's own copy of the title, which can be a Codex prompt, `parentSession`, `previousSessionFiles`, `additionalDirectories` and the two prompt-cache keys are parsed with the line and dropped. A longer header, or one that is not a session's, leaves the file out. A higher version says a newer Oh My Pi wrote it, and the card says so.

### The third line

Of the rest of that piece, only the first 64 bytes of the third line are compared as bytes, for one check, and the rest is dropped. Once a header is found, while those bytes are too few to tell, as before the third line is whole, the 64 bytes where the third line begins are read again alone, each time the slot is read, and compared the same way. Oh My Pi gives the entries of a session it made from a Codex session IDs `codex-<base 36>` (`CA/session/codex-session-store.ts:620`), and saves Codex's title as a model's, `auto` (`:670`). Codex fills an empty title with your first message, so that title can be your first Codex prompt word for word, or a name you or a model gave it in Codex (`:412`, `:531`, `:614`). Oh My Pi's own IDs are 8 hex digits or a snowflake (`CA/session/session-migrations.ts:5-11`), so they never begin with `codex-`. A third line that begins `{"type":"<word>","id":"codex-<number>",` hides an `auto` title. A fork, `persistCopy` and a branched session keep the entry IDs (`CA/session/session-manager.ts:2537-2580`, `:2810-2825`, `:4165-4180`), so the check covers them. A branch taken from before the first entry makes an empty session and copies the title (`CA/session/agent-session.ts:15054-15058`): its title is shown as a model's.

## The newest lines

Each entry is one line, `JSON.stringify` of its fields in the order the code builds them, added at the end (`CA/session/session-manager.ts:1961-1980`, `:2150-2157`). JSON writes a quote inside a string as `\"` and a line break as `\n`, so the bytes a line begins with can only be its own keys. Of each line only its first 1 KiB is compared (`tail.ts`):

- **Exit:** `{"type":"custom","customType":"session_exit","data":{"reason":"` and a word, `","kind":"` and `normal`, `signal`, `fatal` or `process_exit`, then `","recordedAt":"` and a time (`CA/session/session-manager.ts:3770-3774`; `CA/session/agent-session.ts:4205-4237`; `CA/session/exit-diagnostics.ts:38-44`).
- **Tool start:** `{"type":"custom","customType":"tool_execution_start","data":{"toolCallId":"`, one JSON string skipped, at most 512 bytes, and `","toolName":"` (`CA/session/agent-session.ts:4191-4203`). With `ask","startedAt":"` and a time, Oh My Pi's `ask` tool waits for your answer. With any other name, a tool runs.
- **Refusal:** `{"type":"custom","customType":"provider_refusal",`, a provider's refusal of a reply, which ends a turn as a reply does (`CA/session/provider-refusal.ts:12`; `CA/session/agent-session.ts:4731-4737`, `:5597-5600`). Its line's `timestamp` comes after its `data` (`CA/session/session-manager.ts:3771`), which is not read, so a refusal has no time.
- **Message:** `{"type":"message","id":"…","parentId":` and `null` or a string, `,"timestamp":"…"`, perhaps `,"runtime":{…}` of strings, then `,"message":{"role":"` (`CA/session/session-manager.ts:2150-2157`, `:3588`, `:3615-3623`). `user` and `developer` are a prompt, `toolResult` a tool's result, `assistant` a reply. `bashExecution`, `pythonExecution`, `fileMention`, `hookMessage` and `custom` are passed over. Any other role, or a message line of another shape within its first 1 KiB, cannot be read. A reply's or a result's `timestamp` is kept as its time: Oh My Pi takes it with `new Date().toISOString()` as it adds the line (`CA/session/session-manager.ts:171-173`, `:2150-2157`, `:3579-3591`), so an aborted reply or result written after an exit carries the moment it was written, from the same clock as the exit's `recordedAt` (`CA/session/agent-session.ts:4594`, `:4606-4636`, `:4738`). One made only of a time's bytes, digits and `:.TZ+-`, that is not a time of that shape is none, and the line still decides. One that is empty, longer than 64 bytes or holds any other byte is another shape, and the line cannot be read.
- Every other line that begins `{"type":"<word>",` is passed over: the title slot, the header, `model_usage`, `title_change` and the rest.

Only the three times kept, an exit's `recordedAt`, an `ask`'s `startedAt` and a reply's or a tool's result's `timestamp`, are turned into text, as ASCII checked against the shape of a time. A prompt's `timestamp`, and any other line's, is not. No prompt, reply, tool argument, `intent`, `pendingToolCalls`, `model_usage` text, summary, label, goal, `title_change`, `runtime` value or `foreign_session_import` path is ever turned into text.

The newest line that decides decides. When it is a reply, a result or a tool's or an ask's start, the lines before it are looked back over too, past replies, results, tools' and asks' starts and lines passed over, to the first exit, prompt or line that cannot be read. Oh My Pi writes its exit line before it aborts a turn on a quit (`CA/session/agent-session.ts:7202`, `:7215-7221`). It goes on writing until it stops forwarding (`:7305`). Before that it runs the extensions' `session_shutdown` handlers, which have no time limit, while the turn goes on (`:7208`), then aborts the turn and waits up to 5 seconds for its tasks after the prompt (`:638`, `:7222-7230`), up to 3 for auto-learn (`:6983`, `:7231`), on its memory (`:7232`), on a teardown whose waits are up to 3 seconds each (`:7245-7255`, `:7082`), and up to 5 more for the turn to settle (`:7287-7295`). The abort makes an aborted result for each tool call, an aborted reply, and a start line for each call that had not started, which comes before its result (`AG/agent-loop.ts:1633-1660`, `:3557-3565`, `:3642-3652`, `:4002-4011`, `:4147-4165`). So:

- An exit with only replies, results and lines passed over after it is the exit behind, and decides as an exit does.
- A prompt after the exit, as a resumed session writes (`CA/session/session-context.ts:809-810`), ends the look back, so the exit decides nothing, whatever the times.
- An exit followed by Oh My Pi's own aborted lines decides too, when the newest line is a reply or a result whose own `timestamp` is within 15 seconds of the exit. "Within" runs from the exit's `recordedAt` to 15 seconds after it, and is judged on every poll. A reply or a result whose time cannot be read, as a refusal's, or is more than a minute ahead of the clock, takes nothing. The file's last write is not looked at for this. 15 seconds covers a turn that stops at once, not the longest of these waits.
- A turn whose newest aborted reply or result comes later reads as if no exit had been written.
- While a tool's or an ask's start is the newest line after such an exit, the exit decides nothing, so a quick `/retry` or `--restore` round shows as working and a restored ask still needs you. Oh My Pi can leave a start newest for good, as when it stops forwarding between a call's start and its result (`CA/session/agent-session.ts:7285-7305`).
- A round run after the exit with no prompt, as `/retry` and `omp --restore` run (`CA/slash-commands/builtin-lifecycle.ts:481`; `CA/session/agent-session.ts:13918-13934`; `CA/session/turn-recovery.ts:3648-3684`), writes the same lines. Once it has started a tool and its newest reply or result is written more than 15 seconds after the exit, it too reads as if no exit had been written.
- A later write with no prompt, as a rename from the picker or `/rename` makes (`CA/session/session-manager.ts:3463-3500`, `:3515-3544`), adds a `title_change` line, which is passed over (`:2004-2062`), and moves the file's last write, which this does not look at. So the session stays finished or failed since the exit. A session that ended with no exit, as one `/new` or `/resume` moved from after a turn (`CA/session/agent-session.ts:12767-12860`, `:14500-14627`), stays finished after such a rename too, since the time on its newest line, when that is a reply or a result, as [Status](#status) says.
- An exit whose `recordedAt` is before the header's `timestamp` decides nothing, whether it is the newest line, the exit behind or followed by aborted lines. A fork and a branch copy each line with the time it had under a header they stamp as they copy (`CA/session/session-manager.ts:2546-2576`, `:4165-4198`, `:4331-4351`, `:2090-2100`), so such an exit is taken as the session copied's, not the copy's. An import holds no exit, as it is made from a Claude or Codex session (`CA/session/foreign-session-import.ts:9-11`, `:36-52`). So a copy reads as if no exit had been written: a copy of a session that ended is not finished while the `omp` that made it runs, is finished, not failed, once none does, and on Windows is unknown. A header whose time cannot be right lets every exit decide.

So a turn cut off by a quit, a signal or an error still reads as ended. When a tool's start follows the exit, that holds only while a reply or a result is newest and its own time is within 15 seconds of the exit.

The first time, the end is read backwards, 64 KiB at a time, to the line that decides and any exit before it, looking through at most 8 MiB and the byte before them. At most one piece and 2 KiB are held at once. After that, only what was added is read, onwards, a piece at a time, when the file is no shorter than when it was last read, grew by 8 MiB or less, and the byte before what was added is a line break. Otherwise it is read from its end again, as after a shrink, a new identity or a jump of more than 8 MiB. Either way the same lines decide. A line that decides, or an exit before it, that begins more than 8 MiB before the end is too far back, as a first read would not reach it. A last line with no line break waits until it is whole. A file none of whose lines decides, as a header-only file `/new` makes (`DOC:614`), is not shown.

## Status

"The last write" is the time on the newest line that decides when that is a reply or a result, or the header's `timestamp` when that is later, and never later than the file's last write, and otherwise the file's last write. An `omp` that writes a reply or a result started before the time it puts on the line, and one that makes a copy, as a fork, a branch and an import do, which keep each line's time, started before the header it writes (`CA/session/session-manager.ts:2546-2563`, `:2814`, `:2090-2100`, `:4184-4198`; `CA/session/foreign-session-import.ts:51`). So a later write that decides nothing, as a rename from another `omp`'s picker makes, neither backs a session again nor moves when it finished. For a prompt, a tool's or an ask's start, and a reply or a result whose time cannot be right, as a refusal's, it is the file's last write. "Backed" means `ps` lists a program named `omp` or `.omp-wrapped` that started at or before the last write and a minute after, as `ps` can move a start by that much. "Gone" means no program named `omp`, `.omp-wrapped` or, on macOS, `bun` started by then, by an answer asked 2 seconds or more after the last write, or the last write was more than a minute before the computer started. "Recent" means the file's last write could be right and is less than 30 minutes old. The first row that holds wins:

| Row | When                                                                                                                                                                                                                              | Status    | Since                             |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | --------------------------------- |
| 1   | An exit of kind `fatal`, not from before the header's `timestamp`, is the newest line, the exit behind it, or followed by Oh My Pi's own aborted lines, with a reply or a result newest whose own time is within 15 seconds of it | failed    | its `recordedAt`                  |
| 2   | The same, of any other kind                                                                                                                                                                                                       | finished  | its `recordedAt`                  |
| 3   | Gone                                                                                                                                                                                                                              | finished  | the last write                    |
| 4   | The newest line cannot be read, or is too far back                                                                                                                                                                                | unknown   | none                              |
| 5   | The `ask` tool waits, backed and recent                                                                                                                                                                                           | needs you | the ask's `startedAt`             |
| 6   | A prompt, a result or a tool's start is newest, backed and recent                                                                                                                                                                 | working   | none, the file's last write shown |
| 7   | Anything else, a reply among them                                                                                                                                                                                                 | unknown   | none                              |

Every time is judged against the clock on every poll: one more than a minute ahead is none. An exit whose time cannot be right, or is before the header's, finishes nothing by itself. When a tool's start follows an exit, a newest tool's or ask's start, or a newest reply or result whose own time is not within 15 seconds of it, reads as if no exit had been written, whenever the file was last written. A needs-you time is the ask's own and does not move while cache warming writes. Idle never shows: nothing written says a turn is over and the session waits for its next prompt.

### Known limits

- **Working while it is not, for up to 30 minutes after the file's last write:** a turn a crash left while another `omp` runs; a turn that ends with nothing written, as after a context-overflow error with no content that compaction does not go on from (`CA/session/agent-session.ts:5601-5608`); a session left mid-turn by `/new`, `/resume`, a fork or a model switch (`:4638-4667`); a reply cut off while it named a tool (`CA/session/turn-recovery.ts:3620-3630`); a turn a crash left on a prompt or a tool's start whose file a picker rename in another `omp`, or `/rename` once it is resumed, wrote again (`CA/session/session-manager.ts:3463-3500`, `:3515-3544`); and a fork, a branch or an import of a session that ended on a tool's result, while the `omp` that made it runs, before its next prompt.
- **A second Finished after a rename:** a session a crash left on a prompt, a tool's or an ask's start, that ended on a refusal, or a copy whose newest line is the exit it copied, once finished because no `omp` could still write it, is not finished while another `omp` whose picker renamed it runs, as its last write is the file's. It shows as working, or as needing you with a notification again, for up to 30 minutes after the rename, and as unknown after that, after a refusal or after a copied exit. Once that `omp` quits it is finished again, since the rename, so a Finished notification goes out a second time. A session that ended on a reply or a result stays finished since that line, or since its header when that is later, as for a copy.
- **Waits inside a tool show as working:** approvals (`CA/extensibility/extensions/wrapper.ts:355-470`), plan review, `computer.control.acquire`, `cfg://` write approvals, the consent of `report_tool_issue` and extension dialogs (`CA/modes/interactive-mode.ts:2710-2725`). They show as working until 30 minutes after the file's last write, which cache warming can move (`CA/session/agent-session.ts:6688-6713`).
- **Finished while open:** a session reopened with `--resume`, `--continue`, `/resume` or a restart that stays idle (`CA/modes/interactive-mode.ts:8571-8600`; `CA/session/exit-diagnostics.ts:206-235`), or whose newest line is a reply or a result and that is only renamed, or switched to another model or thinking level, before its next prompt (`CA/session/session-manager.ts:3463-3500`; `CA/session/model-controls.ts:308`, `:597`), as those lines are passed over and its last write is then that line's time, or its header's when that is later, and after `omp --restore` or `/retry`, a model round with no new prompt.
- **Finished during a round after the exit:** a `/retry` or `--restore` round reads as finished while its newest line is a reply or a result and either no tool's or ask's start lies between it and the exit, at any time, or that line's own time is within 15 seconds of the exit.
- **Not finished by its exit:** when a tool's start follows the exit, a turn whose newest aborted reply or result is written more than 15 seconds after it, as a tool slow to stop or slow `session_shutdown` handlers can make it, one whose newest line is a tool's or an ask's start, as when Oh My Pi stops forwarding between a call's start and its result (`CA/session/agent-session.ts:7285-7305`), and one whose newest reply or result has no time that can be right, as a refusal has none, each read as if no exit had been written: on macOS and Linux each is finished, not failed, since its last write, once no `omp` that could have written it runs, and on Windows each is unknown.
- **An exit before its header:** an exit is judged by the clock that wrote it. When the clock is set back past a session's header before Oh My Pi writes its exit, that exit decides nothing, as a copied one does, so a crash shows as finished by `ps`, not failed, and on Windows as unknown. While the header is more than a minute ahead of the clock, every exit decides. Once the clock is within a minute of it, an exit from before it stops deciding, so a failed session can turn finished with nothing written, and a Finished notification can follow the Failed one. A session moved from a computer whose clock is ahead of this one's can do the same.
- **Unknown:** the aborted reply after Esc during a tool, a long `task` run once the parent's file has been quiet for 30 minutes, and on macOS a session no `omp` backs, unless Oh My Pi wrote that it stopped, while a `bun` that started before its last write, or within a minute after, runs.
- **A reply that failed is not read.** Auto-retry keeps the error in the file and adds its recovery (`CA/session/turn-recovery.ts:1127-1137`), and a wait for a usage limit sleeps until the limit resets (`:3340-3375`), so a failed reply reads the same while Oh My Pi retries it.
- **A line off the current branch:** an entry Oh My Pi adds to another branch (`appendMessageToBranch`, `CA/session/session-manager.ts:3597-3623`) reads as the newest line.

## Whether a program could still write it

The session-owner record is never opened, listed or probed. It is an empty `flock` file only on macOS and other non-Linux Unix, an abstract socket on Linux and a named mutex on Windows (`NAT/file_lock/mod.rs:1-6`, `:32-40`; `DOC:625`). It holds no pid, it is never removed, `flock` has no question that does not take or try the lock, and Oh My Pi's own look needs `fcntl`, `connect` or a listing of the system's objects. Taking or trying it could move a session Oh My Pi then writes to a sibling file with a new ID (`DOC:626`). Reading `/proc/net/unix` would read every program's socket names, so it is not done. Nor is any socket of the daemon or IRC used, nor any terminal record of Oh My Pi's read.

On macOS and Linux, while a shown session's status depends on it, Agent Lookout runs `ps -A -o pid=,lstart=,comm=`, in UTC, at most every 10 seconds, and sooner, though not within 2 seconds of the last ask, when a session is written after an answer that listed no `omp`, `.omp-wrapped` or, on macOS, `bun`, or up to 2 seconds before. A clock set back counts as time enough, and for files read as the poll that asked read them, allows no 2 seconds. It keeps only the start times of the programs of those names and whether its own process was listed: an answer that does not list it is not used. On macOS, after the clock is set back by more than a minute, a write stamped between the time it was set back to and the latest time seen is not finished by a start that looks later. When the computer started is the earliest worked out while Agent Lookout runs, from `os.uptime()`. A session decided by an exit, or last written more than a minute before the computer started, needs no `ps`.

### Names of the program

- `omp` is the command as its installer, Homebrew and its released binaries name it, and as it names itself on Linux once it starts (`UT/process-name.ts:1-18`, `:32-61`; `CA/cli.ts:107-112`). `.omp-wrapped` is the command as Nix runs it on Linux before it names itself (`nix/package.nix:230-236`). Both back a session.
- On macOS Oh My Pi sets only `process.title`, which does not reach `ps` in Bun, so an `omp` installed with `bun install -g` runs as `bun` (`UT/process-name.ts:5-17`). `bun` is a name that may write a session and backs none, on macOS only. With only `bun` running, working and needs you never show, and any other `bun` that started before a crash-left session's last write, or within a minute after, such as a dev server, keeps that session unknown instead of finished.
- On Linux `omp daemon` and `omp tiny …` do not match (`CA/daemon/server.ts:538`; `CA/tiny/worker.ts:265`). Worker processes name themselves `omp` (`CA/cli.ts:513-516`), and on macOS the daemon runs as `omp`, so either can back a session. The 30 minutes bound that.

## Names and folder

The name is the slot's title when its source is `user`, or `auto` and the session is not a Codex session's copy, else the folder's, the last part of the header's `cwd`, else the ID. A leading run of 1 to 8 code points of a font's own and the space after it, the icon Oh My Pi's title card puts first (`CA/utils/title-card.ts:43`, `:49-56`, `:102-104`), is dropped. An emoji is kept. Then it is cleaned and cut as every name is.

- `auto` titles are a model's, at most 80 characters and 12 words, and they can keep your words and their casing (`CA/tiny/text.ts:211-232`).
- `/rename` with no argument writes a model's title marked `user` (`DOC:447`).
- Names set by an extension, RPC or ACP are marked `user` (`CA/modes/runtime-init.ts:137-140`; `CA/modes/rpc/rpc-mode.ts:2690-2700`; `CA/modes/acp/acp-agent.ts:3351`).
- A Claude Code session's copy marks a Claude Code rename `user` and an `ai-title` `auto` (`CA/session/claude-session-store.ts:485-488`).
- `title_change` lines and the header's title are never used. With `--no-title` or `PI_NO_TITLE` there is no title, and the folder's name shows.

The folder is the header's `cwd`. The name of the folder Oh My Pi keeps a project's files in is never shown or kept.

## Quiet for, tokens, Jump, Stop and Answer

Quiet for is the time since the file's last write, while a session works, for up to 30 minutes. Tokens are not read: Oh My Pi keeps a request's counts beside its prompt and reply text. There is no Jump: the file names no process, and the terminal records Oh My Pi keeps, `terminal-sessions/<tty>`, are not read. A later change could match them with `ps`'s terminal once this adapter has been checked on a computer running Oh My Pi. There is no Stop and no Answer: Agent Lookout makes no request to Oh My Pi.

## On Windows

`ps` is not run, and the way read is `files-without-processes`. A session shows as finished or failed only once Oh My Pi writes that it stopped, and as unknown otherwise, a question from `ask` among them, since nothing can check that the `omp` that asked still runs. If a rename by Oh My Pi fails with `EPERM`, it moves the old file aside as `<name>.jsonl.<snowflake>.bak` (`CA/session/session-storage.ts:1041-1045`, `:1211-1225`). Each open is kept short. Under WSL, pointed at Windows' `.omp`, `ps` sees no Windows program, so every session there shows as finished 2 seconds after its last write.

## The Pi family

Pi, Kimchi and Prime Agent share Pi's adapter body. Droid and Oh My Pi are adapters of their own that share pieces of Pi's: a change to `pi/sessionFiles.ts` or to `SESSION_ID`, `INSTANT`, `folder` or `parseHeader` in `pi/sessionFile.ts` changes Oh My Pi too, and so does a change to `deepseek-harness/processes.ts`. Oh My Pi reads `PI_CODING_AGENT_DIR` and `PI_CODING_AGENT_SESSION_DIR`, as Pi does, so both adapters can read one folder: a Pi file there has its first 256 bytes read by this adapter and nothing turned into text.

## What breaks when Oh My Pi changes

- The slot's size or `v`, or the order of its keys.
- The order of the header's keys, or of a message's or `custom` entry's, or of the data of `session_exit` and `tool_execution_start`.
- When an entry's `timestamp` is taken: as its line is added, from the clock an exit's `recordedAt` comes from.
- The names `session_exit`, `tool_execution_start`, `provider_refusal` and `ask`, and the kinds of an exit.
- The `codex-` IDs of a Codex session's copy.
- How a project's folder is named, or where the sessions folder is: the variables `PI_CODING_AGENT_DIR`, `PI_CODING_AGENT_SESSION_DIR`, `PI_CONFIG_DIR`, `OMP_PROFILE`, `PI_PROFILE` and `XDG_DATA_HOME`.
- The program's names, `omp` and `.omp-wrapped`, and on macOS `bun`.
- The other files it never opens: `agent.db`, which holds settings and sign-ins (`UT/dirs.ts:985-988`), `secret-placeholder.key` (`:1137-1140`), `run/daemon` (`:1144-1146`), `browser-profiles/` (`:839-841`), `memories/` (`:1065-1067`) and the snapshot cache of the auth broker, `cache/auth-broker-snapshot.enc` (`:905-911`). A new one beside the session files that ends in `.jsonl` would be looked at.
