In short

It finds the sessions already running

It reads the list of sessions Claude Code keeps, the session files Codex saves and the transcripts the Antigravity CLI keeps. A session in a terminal, in VS Code or in a desktop app appears with no setup, and any other agent can show its sessions by writing a small status file. Another machine’s sessions can be read over SSH too, from the Agent Lookout running there. Agent Lookout starts nothing.

It shows which one needs you

A Claude Code session that stops for permission or asks you a question moves to the top of the page, with its reason, what it is asking and a timer. With the Agent Lookout plugin installed in Claude Code, a permission prompt shows its whole command, with Deny and Allow. The browser tab counts the sessions that are waiting, as in (1) Agent Lookout, and so do the Mac app’s menu bar and Dock icon. Once you turn notifications on, your browser or your Mac tells you when one starts waiting, and in the Mac app the notification and the menu bar have Deny, and Allow when the whole command shows. An Antigravity CLI session moves to the top while agy asks you to approve a command.

Nothing needs you the lamp in the mark is out
A session is waiting the lamp is lit, on every view

Codex does not record that it is waiting, so a Codex session shows as working, idle or finished, and so does an Antigravity CLI session that asks you a question.

By default it sends nothing anywhere

The one exception is the Mac app, which asks GitHub about once a day whether a newer version is out, sends nothing about your sessions, and stops asking when you turn that off in its Settings. Email, a Slack-compatible webhook and phone pushes through ntfy or Pushover are off until you set them up, and then send only what PRIVACY.md lists. Pull requests are off too, and once on, your own gh sends GitHub the names of the repository and branch. Another machine is read only once you name it, through your own ssh. It does run Claude Code’s own listing command, which may contact Anthropic the way Claude Code normally does. PRIVACY.md lists everything it reads and runs.

How to get it

Download the Mac app, or start Agent Lookout with Node.js in one of the other three ways and open it as a page in your browser.

View on GitHub
  1. 1

    Download the Mac app

    Download the disk image for Apple silicon or for Intel from the latest release on GitHub, open it and drag Agent Lookout to Applications. It needs macOS 13 Ventura or later, and no Node.js.

    The first time you open it, macOS says “Agent Lookout” Not Opened: press Done, then Open Anyway in System Settings › Privacy & Security. Kept in Applications, it updates itself from later releases.

  2. 2

    Start it with one command

    You need Node.js 22.12 or newer, and Claude Code, Codex or the Antigravity CLI. 

    npx agent-lookout

    The first time, npm asks Ok to proceed? (y): press Enter, and it downloads under 2 MB. Then it prints Agent Lookout is running at http://127.0.0.1:4777. Open that address, and your sessions appear within a few seconds. It listens on this machine only and runs until you press Ctrl+C. --port picks another port, and --open opens the page in your browser. To update, run npx agent-lookout@latest.

  3. 3

    Let your coding agent start it

    Paste the prompt in the README’s Install with your agent into Claude Code, Codex or another coding agent. It checks your Node.js, starts Agent Lookout with npx and checks that it answers. When the agent’s session ends, Agent Lookout can stop with it. If the page then says it has stopped updating, run npx agent-lookout yourself.

  4. 4

    Run it from the repository

    Run it this way to read or change its code. It needs the same Node.js.

    git clone https://github.com/Olanetsoft/agent-lookout.git
cd agent-lookout
npm install
npm run build
npm start

    npm start prints the same address, http://127.0.0.1:4777. To update, run git pull, then npm install and npm run build again.

The install guide has every step, with what each command prints. The guide explains each part of the screen.

What it does today

It watches your sessions, here and on another machine over SSH, and notifies you if you ask it to. For Claude Code it also takes you to a session, stops one when you press Stop and confirm, copies the command that resumes one that has ended, and answers a permission prompt when you press Allow or Deny, or by a permission rule you set.

Runs on
macOS, Linux and Windows, as a local page in your browser, and on a Mac as an app that updates itself and counts in the menu bar the sessions that need you. Linux and Windows are checked in CI, not yet by a person at a desktop. On Windows, Stop, Allow and Deny, permission rules, Resume, Jump to tmux, Terminal or iTerm2, and notifications with no tab open are not offered: On Windows says why.
Finds
Claude Code, Codex and Antigravity CLI sessions already running, in a terminal, in VS Code or in a desktop app, and the sessions of any agent that writes a status file.
Other machines
Another computer’s sessions, beside this one’s, once you name it in AGENT_LOOKOUT_REMOTES. It needs Agent Lookout running there, and is read through your own ssh. Its sessions have no Jump, Stop, Allow or Deny.
Claude Code
Shows which sessions are waiting for you, why and for how long, and what each one is asking, such as Run: npm test.
Codex
Shows a session as working, idle or finished. Codex does not record that it is waiting, so Agent Lookout cannot show it. It has been checked with the Codex desktop app, and not yet with the Codex CLI or its IDE extension.
Antigravity CLI
Shows a session as working, idle, failed or finished, named by the title agy gives it, and as waiting for you while agy asks you to approve a command. A question it asks you shows as working. Built from agy 1.3.1 and checked against one conversation.
Sessions
Each one’s git branch, grouped by repository if you choose, as a list or a board, with a search (/, or ⌘K on a Mac and Ctrl+K elsewhere) and a page of details for each. With pull requests on, the details show the branch’s pull request and its checks, through your own gh.
History
The Events log and the charts are kept on this computer across restarts, for 8 days, and Settings clears them. Waits says how long sessions waited on you today and over 7 days.
Notifications
Off until you turn them on. Then your browser tells you when a session starts waiting, and, as you choose, when one finishes, fails or ends. On a Mac, Agent Lookout tells you itself once the tab is closed. Nothing is sent off your computer.
Time rules
Off until you turn them on in Settings. One reminds you of a long wait, and again every few minutes while it goes on if you choose, one sets how long a session is idle before it is stale, and quiet hours hold notifications, emails and posts back, with one summary when they end.
Email, webhook and phone
Off until you set them up. Then an email, a post to a Slack-compatible webhook, or a push to your phone through ntfy or Pushover, when a session has waited a minute, and, if you choose, when one finishes, fails or ends. What the session is asking goes in only if you turn that on too.
Jump
Opens a Claude Code session that runs in VS Code, selects its pane when it runs inside tmux, and brings its tab forward in Terminal or iTerm2 (macOS asks once whether that is allowed). Codex and Antigravity CLI sessions, sessions in Claude Code’s desktop app and sessions in other terminals outside tmux have no Jump button.
From a terminal
agent-lookout status prints which sessions need you, and agent-lookout mcp lets an agent ask the same. Both only read.
Stop
Stop, in a Claude Code session’s details, ends its process, and End all… ends the sessions left running, idle a day or more or as long as the idle rule says. Each asks first. Agent Lookout never stops a session on its own, nor one in Claude Code’s desktop app. The conversation is kept.
Resume
Copies the command that continues a Claude Code session that has ended, cd to its folder and claude --resume with its ID, for you to run in a terminal. A background job that finished, failed or was stopped has it, and so does a session you stop with Stop, in its details. Agent Lookout runs nothing, and a session still running has no Resume.
Allow and Deny
With the Agent Lookout plugin installed in Claude Code, a session waiting for permission shows Allow and Deny on the dashboard, and in the Mac app on its notification and in its menu bar. The whole command is shown first, every line, and an edit, a plan, a question, or a request that cannot be shown whole can only be denied there. The prompt in the session still works, and whichever you answer first wins. Agent Lookout answers only when you press one or a permission rule you set matches, rewrites no command and saves no rule in Claude Code.
Permission rules
None until you add one in Settings. With the plugin installed, a rule decides how a kind of Claude Code permission prompt is answered: always allow, always ask or always deny, by tool and, for Bash, by command, such as npm test:*. An allow rule answers only what you could allow by hand, for Bash one plain command, and never one that begins with a program on Agent Lookout’s list of those that run another command, send requests or run the code they are given, such as sudo, curl or python. The Events log records each answer.
